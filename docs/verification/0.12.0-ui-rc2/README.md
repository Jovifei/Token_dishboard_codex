# 0.12.0-ui-rc2 · Windows 本机验收

本次在 PR #3 的 `a13922ce216ccc1a0a7f0504d1b18cf77107648e` 上调整用量统计的小窗口布局，使用独立数据和非输入桌面测试。测试不读取真实会话或用量记录。

## 最小窗口与 Tk 缩放

Windows 11 原生 Tk 窗口实际内容区均为 980×680；每个单元格为未滚动时**完整可见的请求行数**，表头均可见。数据为 84 条合成请求。

| Tk 等效缩放 | 近 7 天柱状图 | 全部热力图 |
| --- | ---: | ---: |
| 100%（96 DPI） | 4 | 3 |
| 150%（144 DPI） | 9 | 7 |
| 200%（192 DPI） | 5 | 4 |

对照同一合成数据、同一窗口尺寸与 Tk 缩放的 PR #3 基线：200% 时两种视图都没有露出表头或完整日志。新版以字体与可用空间为依据调整指标卡、图表、筛选与底栏；长数值、未知定价、热力图点击、历史展开和键盘操作另有回归测试。完整日志和筛选仍可通过滚动访问。

[原版 200% 柱状图](before-200-percent-7d.png) · [新版 200% 柱状图](after-200-percent-7d.png) · [新版 200% 热力图](after-200-percent-all.png) · [布局测量](layout.json)

本机主显示器实际为 150%；200% 是在真实 Windows/Tk 进程内设置的缩放，**没有修改 Windows 系统显示缩放**。这不能代替将 Windows 系统实际切到 200% 后的人手验收。

## 测试和便携包

- 首轮全量回归有两项失败：旧测试分别假定“更多指标”始终在滚动区内，以及图表左边距固定。现改为检查实际可见范围、焦点与空格操作，以及柱体相对实际交互区域的位置；两项单独复验通过，最终全量回执独立记录。
- 84 条合成请求演示检查通过。最终 Windows 全量回归 457 项：452 通过、0 失败、0 异常，5 项因普通令牌不能创建文件符号链接而跳过。[回执](windows-tests.json) · [测试日志](windows-test-log.txt)

- Windows x64 便携 EXE 在隔离环境中启动，运行路径不依赖外部 Python；普通和 `.jsonl.zst` 合成日志的读取、跨副本去重及损坏提示通过。
