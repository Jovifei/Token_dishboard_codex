# 轻续 0.10.0-rc4-ui2 · 界面与交互规范

本规范以当前 Tk 源码为依据，说明三页工作台及悬浮窗的操作关系。UI2 的运行截图使用 Linux Tk 和合成数据，Windows 结果另见本机验收。[UI2 设计交接](design/apple-ui-v2/README.md) · [Windows 本机验收](verification/0.10.0-rc4-ui2/README.md)

## 1. 产品任务与页面层级

核心任务是：选择项目和一次聊天，理解最近可读请求的上下文压力，在合适时机整理短交接，再由用户打开同项目新聊天继续。交接文件保存项目目标、约束、已完成与未完成、证据、下一步和按需资料索引，避免新聊天默认加载全部历史或整个知识库。

一级导航固定为“用量概览 / 会话接续 / 设置”。项目和聊天选择器位于主内容顶部，全局共用；接续页不再重复大标题和身份区。手动选择工作目录也能接续，没有日志绑定时用量显示未知。

| 页面 | 一级动作 | 二级动作与作用 |
|---|---|---|
| 用量概览 | 准备交接 | 刷新测量；打开悬浮窗；调整提醒；切换详细记录、ccusage 快照；点击最近活动选择聊天 |
| 接续第 1 步 | 复制旧聊指令 | 进入接收摘要；可展开知识处理、模板编辑和重新生成 |
| 接续第 2 步 | 下一步给新聊发指令 | 粘贴、导入或读取旧聊摘要；可保存为 Markdown；展开最近交接和保存目录 |
| 接续第 3 步 | 复制新聊指令 | 默认携带摘要；可选择读取已保存的 Markdown、展开下一阶段目标或预览 |
| 目录与提醒 | 保存设置 | 浏览、检查和打开目录；确认项目知识绑定、勾选分类及创建缺失模板；选择提醒策略 |
| Codex 配置 | 备份并应用（预览后可用） | 确认目标文件，选择数值方案，调整压缩与输出及主/子 Agent，再勾选并预览 |
| 悬浮窗 | 准备交接 | 所选聊天 / 最近活跃；点击聊天选择；稍后 10 分钟；收起、展开、拖动、隐藏；右键切换本次动效 |

导航和列表选择只改变轻续的工作目标，不在 Codex 中自动点击聊天、发送消息或新建窗口。切换会话或数据源时，未保存摘要需要先处理；用户取消切换则保持原选择和草稿。

依据：[工作台](../work/qingxu/workbench.py)、[接续面板](../work/qingxu/ui_handoff.py)、[监测界面](../work/qingxu/ui_monitor.py)。

P0 优先保证数据、身份和写入状态可信；P1 改善主要流程的可见性与多用户适配。下表是功能映射，实际通过情况以测试与验收文档为准。

| 优先级 | 需要解决的问题 | 本版处理 | 主要位置 |
|---|---|---|---|
| P0 | 把累计用量当成当前上下文；容量与费用混淆 | 概览使用最近请求总量参考，累计记录与 ccusage 快照分开；容量和提醒线均显示来源 | `monitor.py`、`context_usage.py`、`ui_monitor.py` |
| P0 | 切换项目后沿用错误聊天或旧异步结果 | 全局选择绑定项目、目录和聊天；切换后的旧后台结果失效；保存与导入核对身份 | `workbench.py`、`handoff.py` |
| P0 | 尚未落盘就声称“可以从文件恢复” | 摘要写入新版本后读回、校验元数据与 SHA；文件型指令必须引用可核对的保存结果 | `handoff.py`、`ui_handoff.py` |
| P0 | 没有 Obsidian 或登记引擎时不能用 | 普通 Markdown 交接独立可用；知识资料完全可选；临时交接与长期知识更新分开 | `handoff.py`、`preferences.py` |
| P0 | 配置文件写入被当成运行时采用；旧预览覆盖外部修改 | 明确本机参考、文件当前值、准备写入；预览后备份应用，检查冲突并读回；运行时采用另行验证 | `workbench.py`、`app.py`、`config_store.py` |
| P1 | 摘要框和重复标题把主按钮挤到首屏之外 | 去掉重复页头；三步条固定在上；正文可滚；主动作固定在面板底部；窄宽度时动作重排 | `ui_handoff.py` |
| P1 | 用户目录不同且无法改；配置入口分散 | 数据、交接、导出、知识资料和快照目录均可选择；检查和打开就近提供 | `ui_preferences.py` |
| P1 | 小窗被误认为能跟随 Codex 点击 | 提供“轻续所选聊天 / 最近活跃”；说明无法读取 Codex 焦点；支持收起小块与暂缓提醒 | `ui_monitor.py` |
| P1 | 官方、推荐、自定义阈值概念混杂 | 三种轻续提醒策略单独设置；Codex 压缩参数另页预览应用；未知参考保持未知 | `monitor.py`、`ui_preferences.py` |
| P1 | 模板难以适配不同项目 | 可编辑旧聊 / 新聊模板指导语；工具追加必需身份与格式约束，支持下一阶段目标 | `handoff.py`、`ui_handoff.py` |
| P1 | 主从 Agent 配置难以判断将写什么 | 主 Agent 模型与推理、默认子 Agent 模型与推理同组呈现；逐项勾选；继承含义明确 | `workbench.py` |

## 3. 监测来源、阈值与状态

### 数值语义

大数字表示“最近请求总量 / 当前可用参考容量”，是上下文压力参考。它不等于精确的实时上下文长度，也不等于累计费用。参考容量依次采用：本会话报告的运行时压缩线、配置文件参考线、已核对的模型默认值、本次记录的窗口容量。来源不可用时显示未知；不能把缺失值填成 `0%`。

当前工作台向监测传入配置文件参考线和会话日志，`official_limit` 没有接入额外模型目录值。因此，当前“官方参考”监测可使用日志中的运行时压缩线；没有可核验数据时保持未知。配置页显示的本机模型目录参考值，不自动成为当前聊天已采用的监测阈值。

| 策略 | 何时提醒 | 解释要求 |
|---|---|---|
| 官方参考 | 可核验的运行时压缩线；后台也支持显式提供的已核实默认压缩线 | 缺少依据就显示未知，不能拿用户自定义配置冒充官方值 |
| 轻续推荐 | 已知参考压缩线的 80%；只有窗口容量时为窗口的 70% | 这是本产品的提前预警规则，未证明是最佳成本设置，不修改 Codex |
| 用户自定义 | 参考容量的 1–100% 整数，或固定 Token 数 | 明确百分比的分母；超过当前容量提示无效，避免来不及提醒 |

达到提醒线的 90% 时提示“准备交接”，达到提醒线时提示“建议先交接”。样本超过 15 分钟或时间晚于本机时钟时，显示“最后已知值”，不根据它弹出临界提醒。出现压缩事件但尚无压缩后的测量时，显示“等待新测量”，不继续显示旧进度。正常后台刷新约每 15 秒进行，耗时取决于本机数据；不承诺点击 Codex 后立即同步。

| 状态 | 数值和视觉 | 下一步 |
|---|---|---|
| 可以继续 | 可用百分比、来源和时间；绿色文字辅助识别 | 继续当前阶段或主动交接 |
| 准备交接 / 建议先交接 | 琥珀或红色文字与明确状态；提示先别追加大任务 | 打开三步交接 |
| 等待数据 / 提醒线未知 | `—` 或已有 Token 数 + 容量未知；灰色空进度 | 检查选择、数据目录或等待新请求 |
| 最后已知值 | “上次”数值、时间和过期说明 | 刷新或等待新记录，不声称当前安全 |
| 等待新测量 | 说明已发生压缩，不显示压缩前进度 | 等待压缩后的请求记录 |
| 读取失败 | 原因与可恢复动作；不沿用另一聊天数值 | 检查目录、权限并重试 |
| 暂缓 / 提醒暂停 | 保留进度，说明只影响提醒 | 可继续查看；暂缓按聊天隔离 |

悬浮窗“最近活跃”最多显示 4 条，按记录时间排序。准备交接和暂缓操作以轻续所选聊天为目标。小窗支持置顶、收起、拖动与隐藏；本版没有动画宠物。ccusage 区域只读取已有快照，选择目录不会安装或启动采集器。

依据：[监测判断](../work/qingxu/monitor.py)、[样本与新鲜度](../work/qingxu/context_usage.py)、[监测刷新与选择](../work/qingxu/workbench.py)。

## 4. 三步交接的状态闭环

### 第 1 步：旧聊收尾

选择项目和聊天后自动生成旧聊指令预览，这一步不写文件、不改剪贴板。用户点击「复制旧聊指令」，再发送给所选旧聊。旧聊整理项目目标与验收、约束、进度、证据、下一步及按需资料。能写文件时使用指令给出的新路径，否则返回带来源标记的 Markdown。

用户可修改模板指导语；项目身份、输出格式、必要元数据和校验要求仍由工具补齐。复制成功只能说明剪贴板操作完成，不能显示“旧聊已总结”或“知识库已更新”。

### 第 2 步：导入、保存、读回

摘要可直接粘贴并继续生成新聊指令，按需保存为 Markdown。导入文件时会另存版本，保留原文件。无来源标记的普通文件需用户确认项目绑定，有明确错项目身份的文件会被拒绝。旧聊写到预期路径后，可用「读取旧聊保存的文件」直接核对。最近交接只自动读取当前所选来源聊天的版本。

保存结果包括项目标识、工作目录、来源会话 ID、标题、生成时间、摘要 SHA、来源及知识策略。写入采用新文件名和原子提交，不覆盖用户已有文件；之后重新读取并验证。空摘要、超过 16 KiB 的摘要、异常元数据、路径不可写或内容被改动应说明原因，保留输入并提供重试路径。字符或字节上限不能标成 Token 计量。

保存后再编辑正文，状态回到“已编辑，尚未保存”，不能继续把旧文件当作当前正文的有效保存结果。同一已核验文件的未变正文再次保存，无需重复创建版本。

### 第 3 步：新聊继续

| 模式 | 可用条件 | 新聊收到什么 | 状态措辞 |
|---|---|---|---|
| 文件型 `file` | 对应正文已保存并读回；引用文件当前仍能核对 | 简短启动说明、项目目录、来源聊天、文件路径、校验信息及下一阶段目标 | “已复制，等待在同项目新聊天执行” |
| 携带摘要型 `inline` | 有有效非空摘要；可尚未保存 | 自包含摘要、项目与来源身份、下一阶段目标 | 未保存时明确“来自本次粘贴 / 编辑，未验证落盘” |

默认方式为携带摘要。下一阶段目标可展开填写，用于指定新聊先做什么。留空时，新聊按摘要中的未完成项选择下一步。用户在同项目新建聊天并发送指令，再核对新聊是否接续。

依据：[交接保存与提示词](../work/qingxu/handoff.py)、[三步 UI](../work/qingxu/ui_handoff.py)。

## 5. 知识资料与用户可配置项

知识资料支持普通 Markdown 文件夹和 Obsidian。选择当前项目目录并确认绑定后，可勾选需要的七类知识页。保存设置后点击「创建缺失的分类模板」，已有文件保留。接续指令的知识范围同时受当前项目绑定、勾选项和已授权的处理方式约束。

| 策略 | 提示词行为 | 授权边界 |
|---|---|---|
| `none` | 只保存本次交接 | 不请求更新长期知识 |
| `ask` | 先完成交接，再提出值得长期保存的候选内容，并询问用户 | 没得到对应授权前不写知识库 |
| `authorized` | 按已明确授权的目录、范围和内容处理 | 选择此项不等于授予任意知识库写入权限 |

默认未启用、当前项目未绑定或未勾选分类时，有效策略为 `none`。已绑定并勾选分类后可沿用 `ask` 默认值，或在接续页为这次旧聊指令调整。

Codex 数据目录、交接目录、导出目录、知识目录、ccusage 快照目录可选择和检查。更换路径只改变目标。Codex 配置从上到下为目标文件、数值方案、压缩与输出、主/子 Agent。推荐展示可核验的模型参考值，应用时移除勾选数值的覆盖。自定义带入实际文件数值，勾选且留空表示使用默认。应用前先预览，应用后读回。运行时采用需重开 Codex 后单独核对。

依据：[偏好设置](../work/qingxu/preferences.py)、[设置界面](../work/qingxu/ui_preferences.py)、[配置存储](../work/qingxu/config_store.py)。

## 6. 统一状态反馈与布局约束

| 状态 | 显示要求 | 本版对应示例 |
|---|---|---|
| Default | 每个当前步骤只有一个强主动作；次要按钮降低强调 | 复制旧聊指令 / 下一步给新聊发指令 / 复制新聊指令 |
| Hover / Pressed | 约 120 ms 的色彩反馈，保留控件位置、尺寸、焦点和原生点击 | `ui_motion.py` 继承完整 ttk 源样式；减少动效时即时换色 |
| Focus | 键盘顺序与视觉顺序一致；编辑框保留选择、复制、粘贴等常用行为 | 原生 ttk / Text 控件；需在目标系统缩放和输入法下验收 |
| Disabled | 灰化且不触发动作，附近解释所缺前置条件 | 未选聊天、未核验文件型交接、尚未预览的配置应用 |
| Pending | 说明等待什么；保留用户输入；异步刷新防止重复触发 | “刷新中…”；“已编辑，尚未保存”；“待旧聊执行” |
| Success | 只描述真正完成的本地动作，不跨越未验证环节 | “已复制”；“已保存并核对”；“文件写入并读回，运行时待验证” |
| Error | 原因、影响对象和下一步可读；不清空草稿；不会用绿色成功覆盖错误 | 错项目、过长摘要、写失败、配置冲突、不可读日志 |

主窗口以约 1240 × 840 为主要布局，最小 980 × 680。接续与设置正文可滚动，固定底部操作栏独立于正文；窄内容宽度下接续动作重排，不能以“继续滚动寻找主按钮”作为主要使用路径。摘要区默认约 8 行，不重复占用全局页头空间。错误或说明可换行，不依赖红绿颜色本身表达含义。

浅灰背景、白卡片、深色文字、蓝色主动作构成视觉基准；状态以文字辅以颜色。设计稿是信息层级和点击关系的沟通资料，运行控件和原生文件选择器仍须按本机环境验收。Figma 云端文件与额度限制的真实情况见 [设计说明](ui-handoff-0.10.0-rc1/design/README.md)。
