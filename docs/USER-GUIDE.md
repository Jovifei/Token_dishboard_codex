# 轻续使用与交接说明

适用版本：0.10.0-rc2。目标是让长任务在合适的时候收尾，用一份短交接继续工作，同时看清本机日志能提供的用量信息。

## 1. 第一次使用

正常使用时，从 [安装包目录](../install/) 下载并解压 ZIP，双击 `轻续.exe`。程序按 Codex 侧栏列出本机真实项目与聊天标题。想先看样例时，可运行 `Preview-Demo.cmd` 打开标为「合成演示」的窗口。源码的正常入口是 `Start-Qingxu.cmd`。

「设置 → 目录与提醒」中的路径均由使用者选择：

| 位置 | 用途与默认行为 |
|---|---|
| Codex 数据目录 | 包含本机聊天数据库、会话日志和配置的位置；默认来自现有环境设置或用户的 `.codex`。未知或离线时不会伪造用量。 |
| 交接保存目录 | 保存版本化的 Markdown 摘要；不要求放在项目仓库或 Obsidian 中。 |
| 默认导出目录 | 预留统一导出位置；本版本的摘要主保存位置仍以上面的交接目录为准。 |
| 知识资料目录 | 可关闭，也可选普通 Markdown 文件夹或 Obsidian Vault；关闭不影响交接。 |
| ccusage 快照目录 | 可选，读取现有的 `usage-latest.json` 或已配置文件名；这里不是采集器启停按钮。 |

每个目录可输入、浏览、检查、打开。保存会读回偏好文件；摘要/导出目录不存在时，可在明确点击保存时创建。更改位置只更改绑定，不搬移旧文件。数据目录切换遇到未保存摘要会先询问，取消则保留原数据源和草稿。

源码运行的轻续偏好默认保存在 `work/qingxu/data/`。打包 EXE 默认使用 `%LOCALAPPDATA%\Qingxu`。两者都支持环境变量 `QINGXU_DATA_DIR` 指定偏好目录；Codex 数据目录也可在界面选择。若要沿用旧安装版的轻续偏好，先备份，再明确选择同一 `QINGXU_DATA_DIR`；本包不会自动替换旧 EXE 或搬移数据。

## 2. 最常用的三步接续

### 第一步：让旧聊天整理

在顶部选择项目和要收尾的聊天，进入「会话接续」。第一步会自动显示可编辑的旧聊提示词。点 **复制给旧会话**，粘贴到那个仍掌握当前工作的旧聊天发送。

提示词要求旧聊天生成：项目目的和服务对象、当前阶段、本次任务与验收、已完成及证据、未完成及下一步、关键决定与约束、工作区/验证状态、按需资料索引。正文目标约 800—1500 个中文字符；重要状态不能为了字数被省略，较长细节用路径索引。

旧聊天可以返回 Markdown，也可以在有文件权限时保存到提示词给出的精确位置。轻续只生成与复制提示词，**复制成功不代表旧聊天已执行**。

### 第二步：保存交接并核对

旧聊天返回后，回到第二步，选择以下任一种方法：

- 「粘贴摘要」或直接粘贴正文。
- 「导入文件…」选择旧聊天保存的 Markdown。
- 「读取旧聊保存的文件」直接检查第一步给出的目标位置。

检查正文，点 **保存并核对**。看到“已保存并读回”以及明确的文件路径后，才表示本地保存完成。摘要以新版本保存；同一摘要再次保存不会无意义地重复写入。

普通无身份标记的旧摘要需要确认属于当前项目。带轻续身份标记的文件必须通过项目/工作目录校验。来自另一个项目的交接不会被默认为当前项目。文件变化或消失后，文件型续接会拒绝使用旧保存凭据。

### 第三步：交给同项目的新聊天

选择续接方式，可再填写“下一阶段目标”：

| 方式 | 适合什么情况 | 新聊天收到什么 |
|---|---|---|
| 读取交接文件 | 新旧聊天都能访问同一台机器上的保存目录 | 项目身份、文件位置、校验要求、下一阶段目标和按需读取规则；发送前轻续会再读回检查文件。 |
| 携带摘要 | 新聊天读不到该文件，或你想直接粘贴 | 提示词中携带完整短摘要，方便跨窗口使用。未落盘的摘要会明确标注未验证保存。 |

点 **复制给新会话**。自己在 Codex 中新建该项目的新聊天，粘贴并发送。新聊天应先简要说明恢复了哪个项目、做到哪里、第一步是什么，再继续已授权的工作。

文件方式缩短了需要手动粘贴的提示词；文件被读取后仍会进入新聊天上下文。节省来自保留必要摘要、按需取资料及减少重复载入，不能把“放到文件”理解成读取内容不消耗 Token。

已有项目规则、必读文件和权限边界仍应遵守。摘要帮助延续工作，不保证任何模型永远记得所有细节；摘要过期或现场发生变化时，应先核对关键文件。

## 3. 没有 Obsidian 怎么用

直接保持“知识库关闭”即可，三步接续完整可用。需要资料归档时，再选一个普通 Markdown 文件夹。

知识库策略与临时任务交接分开：

- **仅保存交接**：只整理本次短摘要。
- **询问后更新**：由旧聊天提出适合沉淀的知识及目标文件，等待该聊天中的明确处理。
- **按既有授权更新**：只在已有明确范围内更新相关文件，核对后读回；不代表允许修改整个知识库。

工具不会自动扫描全文知识库，也不会自行写真实知识内容。资料索引应记录“路径、用途、何时需要读”，让新聊天按任务取用。没有索引或文件不存在时，提示词要求如实说明，不能伪造同步成功。

## 4. 如何看用量与判断该不该换聊

主页面显示所选聊天，右侧显示最近四条活动。宽度不足时上下排列，可滚动查看。详细记录和 ccusage 日期/项目/主从 Agent 统计保留在次级页签。

进度的分子是日志中的最近请求总量参考，不能与累计用量互换。分母旁边明确标注：本会话报告的运行时压缩线、配置文件参考线、窗口容量或自定义提醒线。配置文件出现某值，不代表当前运行中的会话已经采用。

| 提醒模式 | 这版的行为 |
|---|---|
| 官方参考 | 有可核验的会话运行时压缩线时跟随该线；没有依据显示未知。本轮未接入独立官方默认阈值适配器。 |
| 轻续推荐 | 已知参考压缩线的 80%；只有窗口容量时取窗口的 70%。这是提前收尾规则，不是官方推荐或最优费用保证。 |
| 自定义 | 输入参考容量百分比或固定 Token 数；仅控制轻续提醒，不修改 Codex 自动压缩配置。 |

当用量达到所选提醒线的 90% 时进入提前提醒状态，到达提醒线时建议先保存交接、避免再追加大任务。你可以完成一个较小且明确的收尾动作，再开新聊天。旧测量过期、时间异常、未知数据或读失败不会冒充当前进度或触发错误警报。

发现更新的压缩记录后，旧进度会清空，等待压缩后的新测量。未知显示 `—`；真实零才显示 `0%`；历史值标“上次”。没有可靠的“省了多少费用”基线时，本版不展示虚构节省比例。

## 5. 悬浮窗

从侧栏或用量卡打开小窗，可选“所选聊天”或“最近活跃”。**所选聊天跟随的是轻续顶部选择**，不会识别你在 Codex 桌面刚点击了哪个窗口或标签。

点击小窗某条记录会更改轻续的选择；切换时旧数值清空，再读该聊天。最近活跃按记录时间排序，最多四条。警报优先针对轻续所选聊天；没有选择时才参考最近首条，避免别的项目抢占你的当前流程。

“稍后 10 分钟”只暂缓那条会话的提醒，进度继续更新。“准备交接”进入主窗口的三步流程。“收起”变成约 120×64 的小牌，可拖动、展开或隐藏；“隐藏”不退出轻续。

## 6. 主 Agent、子 Agent 与 Codex 配置

在「设置 → Codex 配置」选择并读取目标文件。界面分开显示本机模型目录参考、文件当前值和准备写入值。

勾选要改变的主模型/推理档位、默认子模型/子推理档位，或压缩与输出参数。模型下拉是快捷列表，也可输入本机支持的模型 ID。选“继承”表示移除该文件中的覆盖；没有勾选的项不会写入。

操作顺序：**读取 → 勾选/输入 → 预览修改 → 备份并应用 → 查看读回结果**。如果文件被外部修改，轻续会要求重新读取，避免覆盖变化。恢复使用明确的备份回执，有并发改动时拒绝强行恢复。

修改主模型时，也会检查仍然保留的主推理档位及继承主模型的子 Agent 组合。本机目录没有支持信息时如实显示待核实；不把通用列表当作该模型一定支持。

写后读回只能证明文件内容正确。是否由 Codex 运行时采用，需在你本机重新打开 Codex、开新聊天核对；已有会话仍可能保留旧设置。轻续提醒与 Codex 自动压缩是两套单独设置。

## 7. 遇到问题

- 列表为空：检查 Codex 数据目录；也可用顶部“选择项目目录…”手动接续，无日志时用量保持未知。
- 摘要未读到：核对旧聊天是否真的执行、保存路径是否可读，再使用导入或粘贴方式。
- 切错聊天：未保存编辑有保护；最近交接只自动读取所选源聊天，不偷用同项目另一聊天。
- 配置应用按钮禁用：先读取文件并产生有变化的有效预览；单纯查看不会启用应用。
- ccusage 为空：确认快照文件位置与格式。未连接快照不等于采集器已经停止。
- 启动失败：检查 Python 版本/Tk，并查看轻续偏好目录中的 `logs/startup-error.txt`。

本机完整验收见 [LOCAL-ACCEPTANCE.md](LOCAL-ACCEPTANCE.md)。
