# QX-20261126-01 · 改善统计响应与会话接续布局

## 任务和原因

Windows 桌面使用中，「今日用量」进入统计后卡顿。实际近 7 天有一万余条请求时，指标和图表曾部分裁切。接续页中资料处理、文件操作和复选框混在主流程，旧聊生成的来源标记也占据正文空间。

桌面安装的五个相关程序模块与 0.12.0-ui-rc2 发布提交 `5c9e6a53e806c1bedb35b1ee79045e743de463c2` 字节相同。扫描已在后台，扫描完成后的报价、聚合、排序和范围变更仍在 Tk 界面线程执行。大样本也会重复测量表格单元格，翻页时重新排序。

## 改动和影响

- 大范围筛选、计费和表格排序移到后台。合并默认图表和表格更新，快速换范围时丢弃旧结果。分组按点开时汇总，翻页复用排序结果，只绘制一页。复用已解析的时区、请求时间和单次报价指纹。
- 按同一原生布局绘制指标和图表。柱状图采用按可用空间选择的金额刻度、虚线网格和日期提示，全部历史仍显示热力图。侧栏「今日」可用键盘进入今天的统计。
- 接续默认流程是复制旧聊提示词、粘贴旧聊回复、复制新聊提示词。文件、模板和历史放在次要入口。来源标记校验、原始值传递和跨项目保护照常。完整工作目录通过「聊天详情」查看。
- 勾选保留原生文字点击、键盘焦点、空格和禁用状态。共享页标题 18pt，正文 10pt，帮助文字 9pt。候选沿用原索引和交接文件格式，配置及数据迁移不属于本次改动。

交互结构以用户提供的 CC Switch 界面为参考。其官方源码采用 [MIT 许可](https://github.com/farion1231/cc-switch/blob/main/LICENSE)。候选沿用轻续的控件、视觉资源和数据口径。

## 验证

本轮证据为 Windows 原生 Tk 的隔离合成数据。980×680 下用进程内 192 DPI 测试，不等同于将系统显示全局切到 200%。同时检查复选框在 96、144、192 DPI 下的大小与点击方式。统计和接续仅记录合成画面。窗口回调提交、表格就绪和事件间隔分开测量，不以单次数据宣称完整历史已经流畅。

- 分项 Windows 验证回执记录 44 项统计界面通过、16 项主题和键盘通过。接续 50 项，49 通过，1 项普通权限的文件符号链接跳过。计费与索引 100 项，98 通过，2 项同类权限跳过。分项验收之后合并了默认图表和表格的结果更新。记录时最终 Windows 回归已逐项通过 18 项，仍在运行。
- 200% Tk 的 10,000 条近 7 天合成样本首屏显示表头与 6 条完整日志。200,000 条全部历史首屏显示表头与 5 条完整日志。接续提示词编辑区首屏可见高度 86px。[统计图](../verification/2026-11-26-usage-review/statistics-200.png) · [接续图](../verification/2026-11-26-usage-review/handoff-200.png)
- 使用同一合成夹具的一次迭代对照中，20 万条结果交给界面后的提交时间从约 3.95 秒降至约 23 毫秒，表格就绪从 5.38 秒变为 5.84 秒。1 万条就绪时间也出现过回退。真实本机大账本冷索引、系统显示改到 200% 和桌面安装本轮未验收。性能仍需复核，暂留草稿。
