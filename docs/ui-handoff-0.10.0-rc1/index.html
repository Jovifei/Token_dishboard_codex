最常用的流程，只走三步。

1

复制给旧会话

选项目、选旧聊天。把第一步提示词发给掌握现场的旧聊天，让它写出项目目的、当前阶段、证据、断点、下一步和资料索引。

2

保存并核对

粘贴摘要，或读取旧聊保存的文件。看到明确路径和“已保存并读回”，才表示本地交接已保存。

3

复制给新会话

选择文件型或携带摘要型，可填下一阶段目标。自己新建同项目聊天，粘贴发送，确认它从断点继续。

续接方式适用场景需要理解的区别
读取交接文件新聊天能访问保存目录手动粘贴更短；被读取的摘要仍会进入上下文。复制前再次核对文件。
携带摘要新聊天读不到文件或希望直接粘贴正文随提示词带过去。尚未保存的摘要会如实标注未验证落盘。

知识库可以关闭，也可以用普通 Markdown 文件夹或 Obsidian。长期知识处理有“仅交接 / 询问后更新 / 按既有授权更新”三种方式；轻续不自行扫描或写入整个知识库。新聊天应按资料索引读取相关文件，继续遵守项目必读规则。

提醒线与压缩线，分别解释。

官方参考

跟随可核验的会话运行时压缩线；没有依据显示未知。这版没有独立接入官方默认阈值适配器。

轻续推荐

已知参考压缩线的 80%；只有窗口容量时用窗口的 70%。这是提前收尾规则，不代表最优费用。

自定义

设置参考容量百分比或固定 Token 数，只影响轻续的提醒。Codex 自动压缩参数在独立配置页修改。

达到提醒线的 90% 时提前提示，到线后建议先保存交接、避免再追加大任务。正常、临近、到线、未知、历史和压缩后待测分别反馈。这里是最近可读请求的用量参考，不是精确实时上下文、累计用量、订阅额度或账单。

悬浮窗跟随轻续选择。 不会识别 Codex 桌面当前焦点。可显示所选聊天或最近四条活动，按会话暂缓 10 分钟，收成可拖动小牌；隐藏不会退出主程序。

拿回本机，从演示开始。

  1. 解压完整修改包到新目录；保留现有安装版。
  2. 有带 Tcl/Tk 的 Python 3.11+ 时，双击 Preview-Demo.cmd，先试合成数据。
  3. 双击 Start-Qingxu.cmd，选择自己的目录。
  4. 用 Test-Windows.cmd 做本机回归，再完成真实旧聊 → 新聊验收。
  5. 需要独立 EXE 时，在 Windows x64 运行 Build-Windows.cmd。本轮没有预编译 Windows EXE。
