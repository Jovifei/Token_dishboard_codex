# 轻续 0.11.0-billing-rc1 · 计费统计使用指南

本版在“用量概览”中增加“计费统计”，不增加第四个一级导航。原有上下文概览、详细记录、ccusage 快照、会话接续和设置仍保留。当前交付是源码验收候选，不是已发布 Windows EXE。

## 先体验

解压到新目录，用带 Tcl/Tk 的 Python 3.11 或更高版本运行 `Preview-Billing.cmd`。这是 **84 条合成请求** 的独立演示，不代表用户账单；正常启动不会加载这些示例。关闭演示会清理临时数据。

正常使用运行 `Start-Qingxu.cmd`，先在“设置”选择自己的 Codex 数据位置，再打开“用量概览 → 计费统计”。首次打开及点击“同步用量”才扫描请求，切换筛选只重算本地数据，不调用模型。

## 两种金额，不混在一起

**当前价表估算**：把逐请求记录中的 Token 按本地价格表重算。对于订阅登录，这最多是 API 等效 Token 成本，不是订阅账单或额度的金额换算；API 用户也需与供应商正式账单核对。工具调用、存储、税费、订阅费和合同折扣不在本轮估算范围内。

**来源报告金额**：只相加标准导入记录显式提供的 `reported_cost_usd`。没有金额的记录保持未知，不拿估算补缺。它仍是“来源报告，未对账”，不是已核验扣款。

内置单价是 2026-11-11 检索到的官方参考快照，不自动更新。选择“查看官方价格”会由用户主动打开浏览器。第三方中转、私有部署或相同模型名的不同供应商必须单独配置，不能默认套 OpenAI 单价。

## 如何看未知和不完整

金额 `—` 表示价格或用量不足，不是免费。`0` 是有完整已知计量且真实为零。金额旁的 `*` 表示只合计已知部分。

只有 `token_count` 快照/累计值的旧日志不能提供可靠逐请求账单，本版不把累计值反复相加；界面会报告有多少日志没有逐请求记录。压缩格式 `.jsonl.zst` 暂未支持，会显示范围可能不完整。一次刷新有读取预算，大日志可继续点击同步；已读完整且未变的文件不会重新读正文。

成功率只计算记录有明确状态的样本，括号内显示样本数；速度和首字耗时只展示显式采集值的均值，不能从任务总时长猜测。多数原生 Codex 日志缺少这些字段时显示 `—`。

缓存命中率按已知缓存拆分记录的 `缓存读取 / 全部输入` 汇总，包含输入中的缓存读取和写入，不把各请求百分比直接平均。总 Tokens 是输入加输出，包含缓存；它不是当前对话上下文，也不代表全部以原价收费。

## 标准请求导入

示例位于 `docs/billing/sample-requests.json`；混合缓存示例位于 `docs/billing/mixed-cache-example.json`。示例日期固定为 2026-11-11，后续日期导入时需选相应时间范围。日常体验优先用动态日期的 `Preview-Billing.cmd`。

只接受一个 schema 为 `qingxu.requests.v1` 的对象，其 `requests` 为请求数组；JSONL 则每行一个请求对象。文件最大 16 MiB，不导入聊天全文或凭据。必要字段为 `response_id` 和带时区的 `time`；供应商、模型和 `usage` 缺失会保留未知。`usage` 支持 Codex 的 input/output 字段或 Responses 嵌套 details；见工程交接的字段契约。

导入绑定当前 Codex 数据来源，更换来源不会混入此前导入。重复 ID 的相同记录不重复收费，冲突需修正源数据后重新核验。暂未提供一键对接所有第三方客户端或网关的采集器。

## 运行与验收

运行 `Test-Windows.cmd` 复验；需要 EXE 时在准备好锁定构建依赖后运行 `Build-Windows.cmd <不存在的新目录>`。本轮不覆盖原 0.10.0-rc4-ui2 安装包。合并到已有仓库前先查看 `docs/BILLING-HANDOFF.md`，核对基线和未提交改动。
