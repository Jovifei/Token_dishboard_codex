4. 指标、分母、时间范围和去重

聊天来源是 state_5.sqlite 及同目录 .codex-global-state.json。SQLite 以 mode=ro 和 PRAGMA query_only 打开。只有活跃、未归档且符合人类聊天筛选条件的记录进入选择器。工作台只读取当前选中聊天的日志，核对该线程的 UUID、元数据路径、会话根与 session_meta.id。chats.py · context_usage.py

界面指标字段与计算范围、刷新和缺失处理
当前上下文占用估算最近可用 event_msg/token_count.info.last_token_usage 的 total_tokens。窗口优先用同条 info.model_context_window，否则取当前轮 task_started.model_context_window。圆环以「最近请求总数 ÷ 日志窗口」估算，含本次请求输出。可比较时剩余为 window − total。当前聊天的主日志尾部最多 8 MiB，跳过截断行。无窗口或用量超过窗口时只画输入/输出构成，分母为请求总数。新轮开始或后来发生压缩会使旧样本失效，暂显示无样本。
最近请求输入与输出输入含缓存为 total_tokens − output_tokens。normalize 校验它等于原始 input_tokens 或 input_tokens + cache_write_input_tokens。非缓存输入再扣除缓存读取和创建。最近请求的输出已含推理。显示记录的本机时间。无合法字段、对账失败或最近样本被淘汰时不填 0。total_token_usage.total_tokens 只用于识别相邻重复计量，避免把重复记录刷新成新样本。
聊天累计用量token_usage_record.usage 经过同一归一化。只接受 thread_id 为所选聊天且 response_id 非空的记录；同一 ID、相同计量只计一次，不把累计字段相加。非缓存输入、缓存读取、缓存创建、输出的总和为分母。推理是输出子集。主日志与同 UUID 的本机可读日志段。总扫描预算 512 MiB，单行计量读取上限 256 KiB。增量缓存根据 inode/大小/mtime 和边界哈希校验。重复 ID 异值拒绝显示累计，同页最近请求仍可显示。详情显示请求数、段数、跳过和刷新时间。
日期快照独立采集器用 ccusage codex session --since <day> --until <day> --timezone Asia/Shanghai --json --offline，产出 usage-latest.json。usage.summarize 只接受 schema 1 和 ccusage_incremental_tokens_not_billing，核对项目、会话、总量和各分项守恒。源为一个已有日期快照，点击刷新读取。显示日期、时区、finished_utc 与年龄。大于 90 分钟提示可能过期。时间未知、异常和采集器心跳分别显示，回执 PID 无法证明进程身份。缺失或不守恒时清空旧显示。
项目汇总与角色日期快照会话行通过 chats.usage_metadata 重新对照本地项目归属，再由 usage.group_sessions 累加。项目环的分母为全局快照 totalTokens。下钻后的组成图使用选中项目/聊天/角色的总量作分母。未匹配、远程、明确未归类或歧义归属仍入总量。角色展示采集器给出的角色与记录数。项目的当前聊天图是该聊天请求范围；项目总览的分母是日期快照范围。
压缩与提醒读日志中的 compacted 或 context_compacted。提醒分母依序取运行时记录的 model_auto_compact_token_limit、合理的配置文件显式值、日志窗口。最近请求总数 × 100 ≥ 分母 × 提醒百分比时进入提示。过去 15 分钟内的有效样本或压缩事件可触发，历史样本可查看。无阈值和窗口时显示未知。轻续阈值独立于 Codex 实际压缩配置。只监控选中的聊天，异步读完后约 15 秒再查，切换丢弃上一聊天结果。
来源字节和工具诊断response_item 中识别消息角色、工具调用、MCP 命名和结果。来源百分比为分类行的 JSON 字节 ÷ 已分类总字节，含封装和图片编码。调用统计看最近活动前 10 分钟，ID 可用时去重，同一工具 ≥10 次提示。单次最大结果在同一尾部样本内按完整结果行字节比较，≥65,536 字节提示。显示工具名、计次、结果时刻、可用时的调用尾号。MCP 只识别暴露的独立日志事件，聚合调用内部、延迟加载、技能、系统定义和各自精确 token 仍未知。
费用、订阅额度与节省UI 与快照 schema 只使用计量字段。没有价格表、会员额度或真实计费来源，也没有已验证的同任务节省比例。历史账务和可比任务结果需要独立证据，界面不推算金额。

身份优先级与跨线程边界

  • 侧栏文件存在时，以其项目顺序、显式未归类、host 与线程分配为先，结合已知别名；其后用 SQLite 的显式项目 ID、工作树根提示或精确根匹配。多候选保持未归类。独立接力登记只按标准化的绝对 cwd 精确匹配，和 Codex 项目分类是两条关系。
  • 日志累计以当前线程内的独立请求去重。子线程或 fork 的独立记录不并入当前聊天。共享父历史没有跨线程全局请求对账。
  • 采集端 attribution.py 读取 thread_spawn_edges 和 thread_source 分类。对父子关系可回溯父归属，也使用已核实工作树别名。角色可区分 child、fork、guardian、primary 或 unknown。界面日期快照在唯一人类父聊、归属条件满足时把子行归到父聊天。这个分组依赖 ccusage 已产出的会话增量行。重复会话行、fork 继承和跨会话成本仍需独立对照。

6. 续聊与普通 Markdown 知识目录

  1. 已复制 → 待旧聊执行。选项目聊天、点「复制保存指令」，在旧聊粘贴发送。已登记且有版本时，提示词包含绝对项目路径、ID、断点文件和 revision。先执行 semantic-read，以刚读出的版本作为 --expected-revision，将短摘要经 UTF-8 stdin 交给 semantic-save。
  2. 摘要已保存。旧聊执行后再次 semantic-read 核对版本及内容，回轻续点「核对交接摘要」。没有接力时旧聊给出 ≤8192 UTF-8 字节短文本，用户粘贴到「交接摘要」，此文本留在当前窗口，尚未成为文件。
  3. 新聊指令就绪。点「复制恢复指令」。私有模式读取最新有效版本，手动模式把短文本放进指令。新聊天从同项目开始，先核对工作目录、Git/工作区和摘要时间/身份，冲突时核实现场证据。默认按需读相关文件。
  4. 已恢复。需要在真正新 Codex 聊天看到读取、核对及接续下一步的证据。程序没有新聊执行、确认或完成状态存储。当前包仅验证断点读回、指令生成与拦截到的复制调用。

文件名为 sha256(project_id).json，格式 project-relay-private-checkpoint-v1。字段包括 project_id、revision、metadata 与哈希、semantic_summary 与哈希、摘要来源元数据哈希及版本、updated_at。摘要是调用者提供，业务完成状态未知。版本锁及读前读后身份核对防止覆盖。摘要来源哈希与当前元数据哈希不同时标过期；非 Git 项目的覆盖限于根元数据，正文变化未必触发。一个登记项目当前共用一个断点，不绑定到每一条聊天。
